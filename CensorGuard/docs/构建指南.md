# CensorGuard 0.5.0 构建与安装指南

本页负责构建、系统安装和 daemon 升级。DSH profile 接入见 [DSH 插件指南](DSH插件指南.md)。
所有 `make` 命令都在 **CensorGuard 仓库根目录**执行。

安装后用 [手动测试指南](手动测试指南.md) 验证策略拒绝、正常命令放行与审计。

## 快速开始

准备一台具备 BTF 和 BPF LSM 的 Linux 主机，以及 Rust 1.88+、C/C++ 编译工具、
clang/LLVM、bpftool、libbpf 开发包、make。构建 DSH 插件还需要 Node 20+、npm、pnpm。
操作系统工具链需要事先安装；`make deps` 下载项目依赖。

### 只构建全部组件

```bash
cd /path/to/CensorGuard
bash scripts/check-env.sh
make deps                  # 首次联网准备；依赖已缓存时可跳过
make all                   # 检查 + Rust release + BPF + DSH 插件安装包
```

完成后可直接使用以下产物：

| 产物 | 用途 |
| --- | --- |
| `target/release/censorguardd` | daemon |
| `target/release/censorguardctl` | 控制与诊断工具 |
| `target/release/censorguard-grpc` | gRPC 适配器 |
| `bpf/enforce.bpf.o` | BPF 内核数据面 |
| `dist/censorguard-dsh-0.5.0.tgz` | DSH 单包插件 |

### 一键安装并启动（首次安装和升级通用）

```bash
cd /path/to/CensorGuard
bash scripts/check-env.sh
make deps                  # 首次联网准备；依赖已缓存时可跳过
make setup
```

`make setup` 自动完成 `make all`，随后请求 sudo 权限，停止已有服务、安装文件、
创建系统账号和运行目录、启用开机启动、启动新服务，最后输出 `status` 与 `doctor`。
已有 `/etc/censorguard/*.yaml` 会保留。**升级会短暂中断保护**，DSH 插件随后自动重新接入。
如果旧配置不符合 0.5.0 的 `daemon` + `rules` 格式，安装器会在停止服务前报错，先修正配置再执行。

看到 `CensorGuard | Ready` 与 `All checks passed` 即完成系统部署。`No processes attached yet`
表示尚无程序接入；继续按 [DSH 插件指南](DSH插件指南.md) 安装到自己的 profile。

只使用 daemon、不需要 DSH 时，两条命令均可增加 `WITH_DSH=0`：

```bash
make deps WITH_DSH=0
make setup WITH_DSH=0
```

## 命令速查

| 命令 | 做什么 | 修改系统 / 服务 |
| --- | --- | --- |
| `make deps` | 联网获取 Cargo 和插件锁定依赖 | 否 |
| `make all` | 检查并构建所有组件、打包插件 | 否 |
| `make setup` | 完整构建、安装、启用并启动新服务、自检 | 是 |
| `make build` / `make bpf` / `make plugin` | 单独构建 Rust / BPF / 插件包 | 否 |
| `make install` | 构建 Rust/BPF 并复制系统文件 | 是；服务由操作者管理 |
| `make install-files` | 复制已有产物，保留已有配置 | 是；服务由操作者管理 |
| `make package` | 打包系统组件到 `target/dist/` | 否 |
| `make help` | 显示常用入口 | 否 |

构建默认使用本机依赖缓存。没有缓存时先运行 `make deps`；离线机器需事先准备相同
Cargo/pnpm 依赖和系统工具链。`make setup` 使用标准 `/usr`、`/etc` 布局；定制目录或
`DESTDIR` 暂存安装使用 `make install` / `install-files`。

## 展开查看细分步骤

以下各项解释快速入口实际执行的步骤，按需展开；快速安装成功后无需再执行一遍。

<details>
<summary>1. 检查工具链与内核</summary>

```bash
bash scripts/check-env.sh
cat /sys/kernel/security/lsm
ls /sys/kernel/btf/vmlinux
node --version
pnpm --version
```

`lsm` 输出必须含 `bpf`，BTF 文件必须存在。BPF LSM 未启用时，按发行版说明在
内核启动参数的 LSM 列表中加入 `bpf`，再重启。发行版默认设置有差异，以检查结果为准。

| 工具 | 用途 |
| --- | --- |
| Rust 1.88+，rustfmt，clippy | workspace 构建与检查 |
| C/C++ 编译器，make，pkg-config | libbpf shim、构建入口 |
| clang（支持 BPF target），llvm-strip，bpftool | BPF 编译及从 BTF 生成头文件 |
| libbpf / libelf 开发包 | 编译、链接与运行 |
| Node 20+，npm，pnpm | 插件编译、打包、安装到 DSH |
| systemd 工具 | 标准服务部署 |
| Python 3，PyYAML | 部分集成测试，可选 |

`check-env.sh` 检查核心工具链与内核，Node/pnpm 由插件构建入口检查。

</details>

<details>
<summary>2. 获取依赖与静态检查</summary>

```bash
make deps
make check
```

`make deps` 执行 `cargo fetch --locked` 与插件目录中的 `pnpm install --frozen-lockfile`。
`make check` 检查 Rust 格式、严格 Clippy、Shell 和 C 工具语法。

单独准备 Rust 依赖可执行 `make deps WITH_DSH=0`。

</details>

<details>
<summary>3. 构建 BPF 与 Rust release</summary>

```bash
make bpf
make build
```

`make bpf` 从 `/sys/kernel/btf/vmlinux` 生成 `bpf/vmlinux.h`，用 clang 编译
`bpf/enforce.bpf.c`，去除调试符号后生成 `bpf/enforce.bpf.o`。临时文件构建完成后才替换旧产物。

`make build` 编译 daemon、ctl、grpc 三个 release 二进制到 `target/release/`。
要开发调试版可执行 `cargo build --workspace --offline`。

</details>

<details>
<summary>4. 构建并打包 DSH 插件</summary>

```bash
make plugin
```

入口执行插件的 `pnpm build`：Node TypeScript 编译、浏览器 TypeScript 检查、
esbuild 浏览器 bundle 构建，然后通过 `npm pack` 生成 `dist/censorguard-dsh-0.5.0.tgz`。
已安装的编译依赖会复用；缺失时尝试从本机 pnpm 缓存安装，需要联网准备时运行 `make deps`。

包内包括 `dist/`、`lib/client.js`、proto、bundle 补丁和配置检查工具。
安装到 DSH profile 是下一步，见 [DSH 插件指南](DSH插件指南.md)。

</details>

<details>
<summary>5. 手动完成系统安装、升级与启动</summary>

以下是 `make setup` 部署部分的等价操作，适合需要自行安排停机窗口的管理员。
先完成构建，并检查当前配置：

```bash
make all
# 首次安装检查仓库配置；升级时改为 /etc/censorguard/base.yaml
sudo target/release/censorguardd launch --config config/base.yaml --check-config

# 升级时先停止旧服务；首次安装可跳过这一条
sudo systemctl stop censorguardd.service
sudo make install-files
sudo systemd-sysusers /usr/lib/sysusers.d/censorguard.conf
sudo systemd-tmpfiles --create /usr/lib/tmpfiles.d/censorguard.conf
sudo systemctl daemon-reload
sudo systemctl enable --now censorguardd.service
sudo censorguardctl status
sudo censorguardctl doctor
```

首次启动可能需要数秒初始化；`make setup` 会等待就绪后再输出自检结果。
升级时仅安装文件不会替换运行中的进程，必须完成停止与重新启动。
本轮新增监听 socket 身份回填后，unit 需要 `CAP_SYS_PTRACE` 读取其它 UID 的
`/proc/<pid>/fd`；升级时须同时安装新版 unit 并执行 `systemctl daemon-reload`。

| 内容 | 默认安装路径 |
| --- | --- |
| daemon | `/usr/sbin/censorguardd` |
| ctl、grpc | `/usr/bin/censorguardctl`、`/usr/bin/censorguard-grpc` |
| BPF 对象 | `/usr/lib/censorguard/enforce.bpf.o` |
| 启动配置 | `/etc/censorguard/base.yaml` |
| 示例配置 | `/etc/censorguard/standard-dev.yaml`、`high-priv.yaml` |
| systemd unit | `/usr/lib/systemd/system/censorguardd.service` |
| 运行目录 / 持久状态 | `/run/censorguard/`、`/var/lib/censorguard/` |

服务按 `daemon.spawn_grpc` / `grpc_bin` 启动并守护适配器，无需第二个 gRPC unit。

</details>

<details>
<summary>6. 验证、暂存安装与离线打包</summary>

```bash
make test                          # Rust 测试
make plugin-test                   # 插件构建、回归测试、发布包检查
make integration-ctl-output         # 隔离 socket 的终端摘要、JSON 与失败退出码
make integration-install           # /tmp 暂存安装、配置保留与打包验证
make integration-audit-config      # 实际 BPF：八种审计开关、配置/组策略更新、stop/relaunch
make integration-exec-arguments    # 实际 BPF：长参数、脚本解释器、apply/bind 就绪状态
sudo make startup-test             # 实际 BPF 最小启动测试
make integration                   # 完整内核场景，需要 sudo/BPF LSM
make integration-dsh-web DSH_REPO=/path/to/deepseek-harness
```

DSH Web 测试还需上游 Web 已构建、Playwright Chromium 及浏览器运行库；使用隔离 profile
和本地模型桩，不调用真实模型 API。验收结果见 [策略管理验收](策略管理验收.md)。

```bash
make install DESTDIR=/tmp/censorguard-stage
make package
```

系统包位于 `target/dist/`，包含二进制、BPF、unit、文档和 `.yaml.example`，附带 SHA-256。
插件包单独位于 `dist/`；目标机仍需其运行依赖与 DSH。系统包解压后需要把首次部署的
`base.yaml.example` 复制为 `base.yaml`，完成 sysusers/tmpfiles、`daemon-reload` 与服务启动。

</details>

## 日常管理

默认读取 `/etc/censorguard/base.yaml`，通常无需传配置路径。

```bash
sudo censorguardctl status           # 简洁状态摘要
sudo censorguardctl doctor           # 分组健康检查，异常给出处理建议
sudo censorguardctl doctor --verbose # 每项检查的细节
sudo censorguardctl status --json    # 完整数据，供脚本与排障
sudo censorguardctl doctor --json
```

<details>
<summary>查看简洁输出示例</summary>

已接入一个进程树时，`status` 显示：

```text
CensorGuard | Ready

                File    Exec    Network
  Protection    On      On      On
  Audit         On      On      On

  Managed       2 processes / 1 root / 1 domain
  Policy        revision 7 / 1 custom group
  BPF hooks     Healthy
  Base policy   /etc/censorguard/base.yaml
  Groups        censorguard-dsh-default
```

`Base policy` 是运行中 daemon 回报的实际基线配置路径；`Groups` 列出已发布的附加组。
附加组规则通过 `policy apply` 发布并持久保存，原始导入文件路径不作为运行依赖。

`doctor` 正常时显示分组结果；失败时在对应分组下列出原因和处理建议：

```text
CensorGuard | All checks passed (12/12)

  Configuration & state   OK
  Kernel BPF support      OK
  Daemon & hooks          OK
  Local channels          OK
  gRPC adapter            OK
```

需要机器读取的完整字段时使用 `--json`；已有解析默认 JSON 的脚本也需增加该参数。

</details>

| 目的 | 推荐命令 |
| --- | --- |
| 启动服务 | `sudo systemctl start censorguardd.service` |
| 临时停止服务 | `sudo systemctl stop censorguardd.service` |
| 取消开机启动并立即停止 | `sudo systemctl disable --now censorguardd.service` |
| 修改基线或 daemon 配置后重新加载 | `sudo censorguardd reload`（完整重启并等待就绪） |
| 更新二进制和 unit | `make setup` |
| 查看启动失败原因 | `sudo journalctl -u censorguardd.service -n 30 --no-pager` |

`systemctl daemon-reload` 重读 unit；`censorguardd reload` 重启 daemon 以读取配置；
`systemctl restart` 重启服务。前台调试的 `censorguardd launch` 会持续占用终端，Ctrl+C
即停止，停止后无法再 reload。自定义配置只在该场景使用 `--config PATH`，完整命令见
[命令手册](命令手册.md)。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| Cargo/pnpm 离线依赖缺失 | 联网运行 `make deps`，再 `make all` |
| clang/BPF 头文件或 libbpf 缺失 | 安装支持 BPF 的 clang/LLVM、libbpf/libelf 开发包；运行环境检查 |
| BPF 构建目录无写权限 | 修复仓库文件属主；普通用户构建，仅安装阶段使用 sudo |
| 升级保留的配置无法解析 | 改为 `daemon` + `rules`；原附加组通过 `policy apply` 发布 |
| gRPC 端口被占用 | 停止另一个旧实例；systemd 与同路径手动 launch 使用同一实例，勿同时启动 |
| 服务启动失败 | 查看 journal；`doctor --verbose` 检查 BPF、socket、状态和适配器 |
