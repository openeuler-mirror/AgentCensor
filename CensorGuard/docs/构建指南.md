# 构建指南

本文档描述如何在一台 Linux 机器上从源码构建 Censorguard的全部组件:
Rust daemon 与客户端工具、eBPF 数据面、DSH 插件,以及安装到系统与离线打包。

- 系统使用方法见 [使用手册](使用手册.md)
- DSH 插件安装与使用见 [DSH 插件指南](DSH插件指南.md)

## 1. 环境要求

### 1.1 操作系统与内核

| 项 | 要求 | 验证方法 |
|---|---|---|
| 内核 BPF LSM | 必须启用(运行时加载依赖) | `cat /sys/kernel/security/lsm` 输出含 `bpf` |
| BTF | 必须存在(构建期生成 vmlinux.h 与运行时 CO-RE 重定位依赖) | `ls /sys/kernel/btf/vmlinux` 存在 |

主流发行版(openEuler 24.03、较新的 Ubuntu/Fedora)默认满足以上条件。
BPF LSM 未启用时需要在内核启动参数追加 `lsm=...,bpf` 后重启。

### 1.2 工具链

| 工具 | 参考版本 | 用途 |
|---|---|---|
| rustc / cargo | 1.88+| Rust workspace 构建 |
| clang | 17+ | 编译 eBPF C 代码 |
| llvm-strip | 与 clang 同源 | 去除 eBPF 调试符号 |
| bpftool / libbpf | bpftool v7.2 / libbpf 1.2+ | bpftool 构建期生成 vmlinux.h, libbpf 为链接与运行依赖 |
| make / install | — | 构建与安装入口 |
| node / pnpm | node 20+ / pnpm 9 | 仅构建 DSH 插件时需要 |

运行 `scripts/check-env.sh` 可一次性自检工具链:

```bash
./scripts/check-env.sh
```

## 2. 构建 Rust 部分

```bash
make bpf                                        # 编译 eBPF C 数据面 → bpf/enforce.bpf.o
cargo build --workspace --release --offline     # 编译全部 Rust crate(release)
```

或一步完成静态检查 + BPF + release 构建:

```bash
cargo fetch --locked
make all
```

> `--offline` 要求依赖已在本机 cargo 缓存中(首次联网构建可去掉)。

`make bpf` 采用"编译到 `.tmp` 临时文件 + 原子 `mv` 替换"的写法:旧
`enforce.bpf.o` 即使属主是 root(曾用 `sudo make bpf` 编译过)或正被
其它进程读取,也不会阻塞普通用户的重新构建。若历史遗留文件导致 `mv`
报权限错误,一次性修复属主即可:

```bash
sudo chown $(id -u):$(id -g) bpf/enforce.bpf.o
```

### 2.1 产物清单

| 产物 | 角色 |
|---|---|
| `target/release/censorguardd` | 特权 daemon:加载 eBPF、维护进程树域、执行策略 |
| `target/release/censorguardctl` | 控制客户端:策略发布、域绑定、进程纳管、运行时开关 |
| `target/release/censorguard-audit` | 审计客户端:订阅事件流 |
| `target/release/censorguard-grpc` | 非特权 gRPC 适配器(127.0.0.1:50051 → ui.sock/events.sock) |
| `target/release/censorguard-exec` | 启动器:供外部宿主登记进程 |
| `bpf/enforce.bpf.o` | eBPF LSM 数据面,由 daemon 在启动时加载 |

### 2.2 单元测试

```bash
make test          # 等价 cargo test --workspace --offline,无需 root
```

## 3. 构建 DSH 插件(可选)

仅当需要 DeepSeek Harness 集成时构建。插件位于 `plugins/dsh-censorguard/`,
自身即单包 `@censorguard/dsh`(`src/` 下分 runtime / bootstrap / host / ui /
client 模块,非 workspace)。

```bash
cd plugins/dsh-censorguard
pnpm install               # 或离线: pnpm install --offline
pnpm build                 # tsc 构建 node 半 + 浏览器半类型检查 + esbuild 产出 lib/client.js
pnpm test                  # 插件单元测试,无需 root
```

构建产物:

| 产物 | 说明 |
|---|---|
| `dist/runtime/` | attach 客户端、心跳守护、状态机(内部模块,无浏览器代码) |
| `dist/bootstrap/` | Cordis 插件入口(`@censorguard/dsh/bootstrap`),attach 后提供 `censorguardReady` |
| `dist/host/` | gRPC 桥(`@censorguard/dsh/host`)、双 RPC 通道、审计流有界缓存;proto 在包根 `proto/` |
| `dist/ui/` + `lib/client.js` | 浏览器半:入口 `@censorguard/dsh`,`lib/client.js` 是 WebUI 加载的 esbuild bundle |
| `cordis.patch.yml` | bundle 补丁层(插件行 + inject 闸门),`dsh plugin add` 后自动进入层列表 |

**注意**:`lib/client.js` 只有运行 build 脚本才会生成,漏掉这步
DSH WebUI 会报 `Cannot find module .../lib/client.js`。pnpm ≥10 首次
`pnpm install` 若拦 esbuild/protobufjs 的构建脚本,插件根的
`pnpm-workspace.yaml` 已将其列入白名单。

## 4. 安装到系统

### 4.1 标准安装

```bash
sudo make install-files
sudo systemd-sysusers /usr/lib/sysusers.d/censorguard.conf
sudo systemd-tmpfiles --create /usr/lib/tmpfiles.d/censorguard.conf
sudo systemctl daemon-reload
sudo systemctl enable --now censorguardd.service
```

`install-files` 的安装布局(`PREFIX` 默认 `/usr`,可用 `DESTDIR` 重定根):

| 内容 | 路径 |
|---|---|
| daemon | `/usr/sbin/censorguardd` |
| ctl / audit / grpc / exec | `/usr/bin/censorguardctl`、`censorguard-audit`、`censorguard-grpc`、`censorguard-exec` |
| BPF 对象 | `/usr/lib/censorguard/enforce.bpf.o` |
| 示例策略 | `/etc/censorguard/base.yaml`、`standard-dev.yaml`、`high-priv.yaml` |
| systemd unit | `/usr/lib/systemd/system/censorguardd.service` |
| sysusers / tmpfiles | `/usr/lib/sysusers.d/`、`/usr/lib/tmpfiles.d/censorguard.conf` |

升级重装**不会覆盖**已有策略配置(Makefile 输出 `preserving existing ...`);
`make uninstall` 同样保留 `/etc/censorguard`。

### 4.2 systemd 部署模型

unit 已内置 `--spawn-grpc --grpc-bin /usr/bin/censorguard-grpc`:daemon 启动时
自动派生并守护 gRPC 适配器子进程(适配器崩溃 1 秒后重启;daemon 退出时
TERM→最多 2 秒→KILL 回收),**无需单独的 grpc systemd unit**。

升级 daemon 二进制时若报 `Text file busy`,先停服务再复制:

```bash
sudo systemctl stop censorguardd
sudo cp target/release/censorguardd /usr/sbin/ && sudo cp target/release/censorguard-grpc /usr/bin/
sudo systemctl start censorguardd
```

> 升级后务必确认 `/usr/sbin/censorguardd` 与 `/usr/bin/censorguard-grpc` 同版本:
> unit 里的新参数旧二进制不识别会导致 daemon 反复崩溃重启。

## 5. 构建验证

```bash
make check                              # fmt/clippy/bash -n/工具语法静态检查
make test                               # Rust 单元测试(无需 root)
sudo ./scripts/test/startup-test.sh     # 0.4.0 最小启动验证(root + BPF LSM)
sudo bash scripts/test/integration-basic.sh   # 基础门禁验收(14 用例,临时目录隔离)
sudo make integration                   # 全量 30+ 场景(文件/exec/网络/DNS/热更/PID 压力等)
```

集成测试需要 root 且内核启用 BPF LSM。全部脚本位于 `scripts/test/`,
`integration-basic.sh` 是合入门禁。

## 6. 离线打包

```bash
make package
```

生成确定性 tar.gz 与 SHA-256 到 `target/dist/`(含二进制、BPF 对象、策略、
systemd 配置),适合在无网络环境的目标机上解包安装。

DSH 插件离线验证(免 root,构造离线 pnpm store 并验证安装流程):

```bash
bash scripts/censorguard-dsh-offline.sh
```

## 7. 常见构建问题

| 现象 | 原因与处理 |
|---|---|
| `cargo build` 报 crates 下载失败 | 未加 `--offline` 时首次构建需联网;或去掉 `--offline` 联网拉取一次 |
| `make bpf` 报 clang 找不到 `bpf/bpf_helpers.h` 等 | clang 版本过旧或头文件路径不符,升级到 17+ |
| `make bpf` 无法覆写/删除 `enforce.bpf.o` | 历史上用 `sudo make bpf` 编译过,文件属主是 root。构建已改为临时文件 + 原子替换,一般不会再遇到;若 `mv` 仍报权限错误,`sudo chown $(id -u):$(id -g) bpf/enforce.bpf.o` 一次修复 |
| daemon 启动报 BTF/BPF LSM 相关错误 | 按 §1.1 验证;`/sys/kernel/security/lsm` 无 `bpf` 时加内核参数重启 |
| 插件 `pnpm build` 报 `@grpc/grpc-js` 缺失 | 依赖未装,先 `pnpm install` |
| DSH WebUI 报 `Cannot find module .../lib/client.js` | esbuild bundle 未构建,`cd plugins/dsh-censorguard && pnpm build` |
| 安装后 daemon 反复重启,日志报 `unknown argument "--spawn-grpc"` | 旧二进制 + 新 unit 不匹配:重新构建并同步安装 daemon 二进制(§4.2) |
| `cp: Text file busy` | 二进制正在运行,先 `systemctl stop` 再复制(§4.2) |
