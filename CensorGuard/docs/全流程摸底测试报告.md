## 原审计配置问题的结论

现场 14:33 启动日志记录 audit 全关；修改磁盘 YAML 后没有 reload/restart，
旧进程继续使用已加载值。单独保存文件不应用配置是当前设计。
实际回归原子替换 YAML，确认 inode 改变后 reload 仍加载新开关和基线，
旧规则移除、新规则实际生效。inode 优先机制针对被保护目标文件，
不会缓存配置 YAML 的内容。已发布组是内容快照，编辑其 YAML 后需要再次 policy apply。

stop 已验证进程退出、五个 socket 释放、托管 gRPC 端口释放，同一 state/path 能再次 launch。
未发现与原日志对应的残留实例。审计只针对已纳管进程；Managed 为零时，
普通 shell 的活动不会产生受控事件。规则 +audit 可独立于全局 ALLOW 开关要求上报，
DENY 仍上报；本轮修复的是这条真实 BPF 逻辑，不只是配置字段和接口。

## 手动测试反馈复验（2026-10-12）

用户使用默认 DSH 组运行 shell 时，`cat /tmp/dsh-guard-test/ro-secret.txt` 被 EXEC
拒绝，`grepconf.sh` 等启动脚本也执行失败。用相同组文件在隔离实例中复现。
这是执行参数检查的实现缺陷，不是参数规则隐式将所有命令改成白名单。

1. 采集 token 达到 32 字节时直接标记失败，而且整个 slot 只要有参数规则，就拒绝
   所有参数采集失败的命令；恰好 31 字节的合法 token 也被误判。
2. 第一次成功的 bprm 检查立刻删除 argv；脚本的后续解释器检查找不到缓存而被拒绝。
3. apply/bind 的操作回执复用 `Response::default()`，没有填写真实 readiness。
   `daemon_ready: false` 是错误的默认值，不是实际 systemd failed 状态；`ok: true`
   和实际版本变化表示该次策略操作成功。

修复为：按可执行文件身份索引参数规则；运行时长 token 不匹配短的完整规则 token，
同时继续检查已命中的参数前缀；恰好 31 字节的 token 正常精确匹配；argv 保留到
脚本/解释器检查结束，在 exec 成功或线程退出时清理（失败 exec 由下次入口替换）。
legacy 操作回执和 RPC 策略操作均填入当前实际 readiness。

新增 `scripts/test/integration-exec-arguments.py`：验证无关命令长 argv、cat 正常执行且
秘密文件由 FILE 拒绝、31/32 字节边界、长尾参数不绕过前缀、字符串身份兜底、普通/
嵌套 shebang、非 leader 线程 exec、shell 子命令，以及脚本参数与解释器 inode 的真实拒绝。
修复前该脚本失败，修复后通过；事件保存于各批次临时目录的 `events.json`。

本轮 Rust 72 项通过，`make check`、BPF 编译和 debug/release 构建通过。

## 参数 token 扩容复验（2026-10-12）

用户指出上一轮消除误拒绝后，参数规则仍限于 31 字节，与整条命令规则路径的
255 字节限制不一致。本轮将 C/Rust 参数 token、argument map key 和事件 args
统一为 256 字节槽（255 字节内容 + NUL），数量仍为 4 槽。长度按 UTF-8 字节计算，
超过上限的规则显式拒绝发布；这不是 Linux 完整路径/argv 的系统上限。

argv capture 从栈迁移到 per-CPU scratch；argument key 扩大为 1024 字节。
事件扩大为 1256 字节，C shim 原固定 512 字节接收缓存改为按 Rust ABI 大小分配；
事件尺寸不一致时显式报错。BPF 字符串路径回退检查读取是否完整，避免 256 字节
运行时路径误命中截短后的 255 字节路径规则。

真实 BPF 验收包括：31/32 与 254/255/256 字节参数边界、255 字节带参数程序路径、
inode 别名、加载时不存在的长路径字符串兜底、256 字节路径不误匹配短前缀、
超过 255 字节的尾参数不绕过拒绝前缀、审计完整保留 255 字节参数、超长规则报错。
原有脚本/解释器、多线程 exec、FILE/EXEC 区分和就绪状态断言也通过。

Rust **73/73**、`make check`、BPF 编译及 debug/release 构建通过；含事件压力的
**10/10 专项集成通过，79 秒**，日志 `/tmp/censorguard-run-all.5GZqt2/`。
没有重跑全部历史集成或真实浏览器流程。新 ABI 需同步安装 daemon/BPF 并重启，
使用 `make setup`；产物未部署到生产系统。
