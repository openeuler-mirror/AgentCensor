# CensorGuard 命令手册

公共命令使用 `/etc/censorguard/base.yaml`，可通过 `--config PATH` 指定另一份启动配置。
路径、权限、组件设置和开关统一放在 `daemon` 段。组策略文件由 `policy apply` 单独发布。

## 组件与概念

| 名称 | 含义 |
| --- | --- |
| `censorguardd` | 特权 eBPF daemon，加载启动配置、维护受控进程树 |
| `censorguardctl` | 策略发布、域绑定、接管与审计入口 |
| `censorguard-grpc` | DSH 委托组管理与事件适配器 |
| base / `__base__` | 启动配置的 `rules`，所有受控 domain 共用的基线 |
| group | 单独发布、可热更新的命名策略组 |
| domain | 受控进程树的归属，可绑定零个、一个或多个 group |
| PID / root | 接管的根进程；已有子孙回填，后续 fork 继承 domain |
| scope | 内核与旧协议中对 domain 的称呼 |

实际约束是 **base + domain 的全部 group**。每一层独立判定，任一层 deny 即拒绝。
网络在每层内先查带端口规则，未命中时回退地址规则；同类规则按最长前缀匹配。
一个组的 allow 不能抵消基线或另一个组的 deny。开关关闭的维度放行。

名称限 1..63 字节 ASCII 字母、数字、`-_.`，区分大小写。
`__base__` 保留，不能作为自定义组或 domain，也不能 apply、bind 或 remove。
DSH 自动域名为 `dsh-<uid>-<tgid>-<starttime>[-hint]`，hint 最长 32 字符，
完整名称仍须满足 63 字节限制。

基线使用逻辑 slot 0。公开组和多组组合的内部有效策略共同占用 slot 1..63；
因此容量上限不是“任意 63 个公开组再加任意组合”。相同组合可共享有效 slot。
slot 由 daemon 分配，与 domain ID、PID 不同，公共命令只使用组名和域名。

## 启动配置与组文件

### daemon 与不可热改的基线

`base.yaml` 只接受 `daemon` 和 `rules` 两个顶层键；未知字段（包括 `groups`、
`domains`）报错。下面是一份启动配置示例；各路径需符合本机安装布局：

```yaml
daemon:
  bpf_object: /usr/lib/censorguard/enforce.bpf.o
  control_socket: /run/censorguard/ctl.sock
  event_socket: /run/censorguard/events.sock
  launch_socket: /run/censorguard/launch.sock
  dsh_socket: /run/censorguard/dsh.sock
  ui_socket: /run/censorguard/ui.sock
  state_dir: /var/lib/censorguard
  socket_group: censorguard
  gateway_user: null
  dsh_self_groups: [censorguard-dsh-default]
  dns_refresh_seconds: 60
  spawn_grpc: true
  grpc_bin: /usr/bin/censorguard-grpc
  grpc_listen: 127.0.0.1:50051
  enable_file: true
  enable_exec: true
  enable_net: true
  audit_file: true
  audit_exec: true
  audit_net: true
rules:
  - file deny+audit /etc/shadow
  - exec deny /usr/bin/nc
```

`daemon` 字段可省略并使用默认值；默认 `spawn_grpc: false`、DNS 间隔 60 秒、
三个 enable 为 true、三个 audit 为 false。上面的示例及仓库 `config/base.yaml`
显式开启 gRPC 和三个 audit，不代表省略字段时的默认值。DNS 间隔必须大于零。
配置文件必须存在。基线规则与 daemon 设置在本次运行期间固定：编辑文件不会
改变正在运行的 daemon，需执行 `censorguardd reload` 或重启服务。

### 可热更新的附加组

每个新增 YAML 文件只接受一个 `rules` 字段，无需写组名、domain 或 daemon：

```yaml
rules:
  - file deny /srv/agent/secret
  - exec deny /usr/bin/git push
```

组名通过 `policy apply --policy GROUP` 指定，绑定通过 `bind` 管理。
逻辑上组规则叠加在基线之后，文件仍独立保存。单行语法见 [使用手册](使用手册.md)。
目录保护、exec 参数数量/长度及通配符限制见 [策略编写与保护范围](策略编写与保护范围.md)。

## 公共命令

### daemon

```text
censorguardd launch [--config PATH] [--check-config] [--duration SECONDS]
censorguardd reload [--config PATH]
censorguardd stop [--config PATH]
censorguardd --version
```

`launch` 是唯一启动入口；`--check-config` 校验启动配置且不加载内核；
`--duration` 用于测试。`reload` 请求正在运行的 daemon 完整重启，重新读取
基线、开关、路径和其它组件设置。它不是组热更新，也不接受 `--file`、`--stdin`。
SIGHUP（包括当前 systemd unit 的 `systemctl reload censorguardd`）请求相同重启。

重启请求在退出前校验配置、依赖文件和待恢复快照；内核加载、权限或组件启动仍可能失败，
`reload` 命令会等待新 boot ID 且 daemon 就绪，最多 30 秒；超时表示请求已接受但结果未确认，
需查看日志。随后可检查 `status` / `doctor`。
完整重启有保护空窗，并清空 PID 注册：手动接管的 agent 要重新 attach，DSH 由心跳重新接入。
若修改 `control_socket`，新配置中的地址还没有监听，使用 `systemctl restart`
或向原实例发送 SIGHUP；普通 reload 命令连接配置当前指定的 control socket。

`stop` 请求运行实例正常退出，并等待 socket 关闭、实例锁释放及托管 gRPC 退出。
它不删除策略快照，也不取消 systemd 的开机启动设置。没有可连接的 daemon 时，
reload/stop 报“no running daemon”；reload 不会启动一个已停止的实例。
reload 必须指定该实例启动时使用的配置路径，不能仅凭相同 socket 换用另一份配置。

launch 是前台运行，Ctrl+C 会停止该实例；systemd 的 ExecStart 也执行 launch，
但由 systemd 在后台管理生命周期、日志与失败重启。不要在同一套 socket/状态目录上
同时使用服务启动和手动 launch。0.5.0 在加载 BPF 前用状态目录与各 socket 的实例锁、
活动 socket 检查和 gRPC 端口预检拒绝重复启动；只在真实绑定后输出 gRPC READY。
托管 gRPC 的首次启动失败会使 daemon 启动失败，清理本次创建的 socket；
成功运行后适配器崩溃仍由 supervisor 重启。遗留锁文件不代表 daemon 仍运行，
是否占用以操作系统文件锁为准，不要在运行中删除锁文件。

| 操作 | 命令 | 含义 |
| --- | --- | --- |
| 手动前台启动 | `censorguardd launch --config PATH` | 直接运行 daemon，终端 Ctrl+C 停止 |
| 手动实例重启 | `censorguardd reload --config PATH` | 请求该运行实例重新读取启动配置，等待新实例就绪 |
| 手动实例停止 | `censorguardd stop --config PATH` | 正常退出，不改变服务是否启用 |
| 服务启动 | `systemctl start censorguardd.service` | systemd 按 unit 的 ExecStart/配置启动 |
| 服务重启 | `systemctl restart censorguardd.service` | systemd 停止后重新执行 ExecStart |
| 服务重载 | `systemctl reload censorguardd.service` | 当前 unit 发送 SIGHUP，daemon 自身完整重启；不等待新 READY |
| 服务停止 | `systemctl stop censorguardd.service` | 停止 unit 及其子进程，保留开机启动设置 |
| 停止且取消开机启动 | `systemctl disable --now censorguardd.service` | disable 加 stop；没有 unenable 命令 |
| 重新读取 unit | `systemctl daemon-reload` | 让 systemd 重新读取服务文件，不重启 CensorGuard 或策略 |

systemd 默认读取 `/etc/censorguard/base.yaml`；手动 launch 读取传入的配置，二者可能
是不同文件。升级二进制/unit 后需 `daemon-reload` 并重启服务；`enable --now` 对
已运行服务不保证换成新进程。新增 stop/reload 需要同版本 daemon 协议；旧服务用
systemctl stop 后升级，不要用新版客户端试图管理旧版生命周期。

### ctl

默认读取 `/etc/censorguard/base.yaml`。日常查看和管理默认使用简洁文本回执；
脚本或完整排障使用 `--json`，逐项检查使用 `doctor --verbose`。自定义实例在命令前加
`--config PATH`。`doctor` 检查不通过时退出码为非零，JSON 的字段结构保持不变。

```text
censorguardctl status
censorguardctl doctor
censorguardctl status --json
censorguardctl doctor --verbose
censorguardctl doctor --json
censorguardctl [--config PATH] policy apply --policy GROUP (--file FILE | --stdin) [--dry-run] [--json]
censorguardctl [--config PATH] policy remove --policy GROUP [--json]
censorguardctl [--config PATH] bind --domain NAME --policy GROUP [--json]
censorguardctl [--config PATH] remove --domain NAME --policy GROUP [--json]
censorguardctl [--config PATH] attach --pid PID [--domain NAME] [--json]
censorguardctl [--config PATH] unattach --pid PID [--json]
censorguardctl [--config PATH] spawn [--domain NAME] [--keep] -- COMMAND [ARGS...]
censorguardctl [--config PATH] audit [--kind file|exec|net|guard] [--domain NAME] [--result allow|deny] [--pid PID]
```

| 命令 | 行为 |
| --- | --- |
| `policy apply` | 发布新组或整组替换同名组；保留基线、其它组和绑定；文件由 ctl 读取并发送内容 |
| `bind` | 给 domain **追加**一个组；重复绑定同一组不会增加成员；域不存在时创建绑定 |
| `remove` | 从指定 domain 移除一个组，其它组与基线保留；最后一个组移除后是 base-only |
| `policy remove` | 删除已经发布的组；任何已发布绑定或活动域仍引用时拒绝，先逐一 remove |
| `attach` | 接管已有根 PID，自动回填已有子孙；不读取组 YAML、不改变绑定 |
| `unattach` | 解除已注册根及其子孙的接管；同域独立注册的其它根及其子树保留 |
| `spawn` | 在目标 exec 前接管，后续 fork 继承；可启动交互式 bash |
| `status` | 显示实际保护/审计开关、基线路径、所有 domain 及其附加策略来源、注册根 PID、未绑定策略；`--json` 输出完整数据 |
| `doctor` | 默认显示分组健康检查和失败建议；`--verbose` 展开细节，`--json` 供脚本使用；失败返回非零 |
| `audit` | 实时输出各检查点的判定；按类型、domain、ALLOW/DENY、PID 组合过滤；kind 同时接受名称和 1/2/3/4 |

默认回执只回答运维问题：操作是否成功、涉及哪个策略/domain/PID、策略从哪里发布、
当前 revision。`--dry-run` 明确显示“只校验、未应用”，失败显示原因并返回非零。
`policy apply`、`bind`、`remove`、`policy remove`、`attach`、`unattach` 的旧 JSON
回执现在需要显式加 `--json`；脚本应检查退出码，再解析 JSON。容量、bank、slot、
计数器及完整规则留在 JSON，日常状态仍保留需要处理的故障提示。

例如发布和查看一个暂未启动进程的 domain：

```text
CensorGuard | Policy applied

  Policy        web
  Source        /root/AgentCensor/CensorGuard/config/policy.dsh-default.yaml
  Revision      11

CensorGuard | Ready
  ...
  Base policy   /etc/censorguard/base.yaml

  dsh-web [configured; no processes]
  ├─ base  /etc/censorguard/base.yaml (inherited)
  └─ web  /root/AgentCensor/CensorGuard/config/policy.dsh-default.yaml

  Group snapshot  /var/lib/censorguard/revisions/12.yaml
  Group policies are saved copies; reapply after editing their source.
```

`configured; no processes` 表示绑定已保存，尚无运行进程；运行域显示注册根数量与 PID。
`draining` 表示域没有注册根、正在清理；若仍有受管子孙则继续保护，直到树排空。
每个域直接以实际名称作为树根；子节点列出继承的基线与绑定的附加组及其路径。
没有附加组的域只显示 base 节点。已发布但未绑定任何域的组另列在 `Unbound policies`。
`--file` 发布记录解析符号链接后的绝对路径；stdin、API/Web 发布显示来源类别及保存快照路径。
旧快照无法还原原始文件名，显示快照路径和 `original source unknown`；从原文件重新 apply 后
记录文件路径。来源仅供追溯：文件变化不会自动更新已发布内容，Web/API 更新会替换旧来源标记。

`rules: []` 清空组内容但保留该组与绑定。更新同名组后，所有引用域自动使用新内容，
无需重新 bind。更换组名时，先 apply 新组，再 bind 新组，最后 remove 旧组；
这段时间两个组同时约束该域。重复 bind 保持成员不变，但不承诺 revision 不变。
`--dry-run` 只校验，不修改 revision 或内核；它只适用于 `policy apply`。

未指定 domain 使用 `default`。没有公开域绑定时，可按合法域名接入 base-only；
有公开绑定后，管理员 attach/spawn 应使用已发布的域。
`unattach` 的 PID 必须是注册根，可从 `status --json` 的 `trees[].nodes[]` 中找 `root: true` 的节点。
接管与解除接管扫描进程树，不追溯已完成的行为，也不提供与并发 fork 完全同步的事务保证。

`spawn` 先停止 helper，接管成功后才执行目标；失败则终止 helper 并返回非零。
退出码沿用目标程序。默认目标退出后解除根注册，仍存活的子孙保持保护直至树排空；
`--keep` 保留根注册。主动 `unattach` 则用于解除仍运行的根及子孙。

`status` 中 `domains[].policies` 为附加组名数组，空数组代表只受基线约束；
`bindings[]` 为已保存的域绑定，包含当前没有进程的域；`domains[]` 继续只表示运行域。
`groups[].source` 为策略来源，`policy_snapshot_path` 为当前持久化快照路径。
`trees[].nodes[]` 提供 `pid`、父 PID、根标记及进程名称，便于后续 attach/unattach。
旧兼容字段 `group` 可能包含组合名，管理时使用 `policies` 内各组名。
观测字段由多次读取组成，不承诺同一瞬间的完整快照。

`doctor` 检查配置解码、BPF object 文件、内核 BTF、BPF LSM、daemon status/hook 状态、
四条业务 socket 可连接性与持久化 current 文件；启用托管 gRPC 时检查 TCP 可连接性。
socket/TCP 可连接不等于业务 RPC 或实际拦截通过，联调仍要执行受控探针。
`audit` 不保存历史，ALLOW 审计由规则 `+audit` 或 `daemon.audit_*` 开启。

### 审计判定与过滤

`--kind` 根据实际发生的操作类型过滤，不读取 YAML 前缀来筛选日志。
它与规则前缀的分类一致，但即使没有命中该类规则，开启全局审计后也会记录 ALLOW。

| kind | 实际观测的操作 | 对应规则类别 |
| --- | --- | --- |
| `1` / `file` | 打开/读取文件、删除、重命名等文件操作 | `file` |
| `2` / `exec` | 执行程序的命令与参数检查 | `exec` |
| `3` / `net` | 连接、绑定、发送/接收等网络操作 | `net` |
| `4` / `guard` | 对 daemon 的信号、ptrace、BPF 等自保护检查 | 内建保护 |

`DECISION` 表示 **OP 所列检查点的放行/拒绝**，不是整条命令的最终执行结果。
例如 `cat secret.txt` 启动时通过 EXEC 检查，随后读文件被 FILE 规则拒绝；同一 PID 会有
`EXEC exec ALLOW /usr/bin/cat` 和 `FILE open_read DENY secret.txt`，cat 最终返回失败。
`rm -rf protected.txt` 同理：可启动 rm，但 `FILE unlink DENY` 拒绝删除。
只有命中 exec 命令/参数规则或执行检查本身拒绝时，才显示 `EXEC DENY`。

例如 rm 的 FILE 事件先显示 `/usr/bin/rm`、动态加载器、libc、locale 等 ALLOW，
表示系统允许读取运行程序所需的文件；随后 `unlink DENY ww-nodelete.txt` 才是对目标
删除操作的拒绝。拒绝后再读取语言文件以输出错误消息，也可能产生 FILE ALLOW，
并不撤销此前的删除拒绝。`COMM` 在 exec 前仍可能是 bash，exec 后变为 rm。
关联事件应看同一次执行的 PID；不同 PID 的两个审计片段属于不同进程。

`--kind exec` / `--kind 2` 只保留 EXEC 事件，**会隐藏 FILE 拒绝**；不会把文件拒绝改写成
执行拒绝。过滤直接检查收到的实际事件类型、域名、判定或进程 ID，不修改策略和保护开关。
多项过滤同时指定时必须全部满足。过滤全部在客户端执行，不会减少内核事件产生量。

```bash
sudo censorguardctl audit --domain dsh-web --result deny  # 该域所有类型的拒绝，适合验证拦截
sudo censorguardctl audit --domain dsh-web --kind file    # 该域文件操作判定
sudo censorguardctl audit --domain dsh-web --kind exec    # 该域执行检查判定；也可用 --kind 2
sudo censorguardctl audit --pid 12345                     # 同一个进程的各类判定，关联启动和文件拒绝
```

`--pid` 使用事件中的 TGID（进程 ID），只匹配该进程，不包含它的子进程；查看整域用
`--domain`。先启动 audit，再触发操作，它不会回放过去的事件。受控 shell 初始化中的
grep、sed、NVM 等程序也属于该域，因此开启 `audit_exec` 时会产生真实 EXEC ALLOW；
手动测试可用 `bash --noprofile --norc` 避免这些初始化命令。
参数中的换行、制表符和控制字符以转义显示，保证每条事件一行；订阅者丢失事件的提示
即使发生在被过滤的事件前也会保留。

## 持久化与切换

成功的 apply/bind/remove 保存私有 `state_dir/revisions/<revision>.yaml` 和 `current`，
不回写输入 YAML。私有快照中的组、来源与绑定用于恢复，不是公共启动配置格式。
每次启动以当前 base.yaml 的基线和 daemon 设置为准，再恢复该 state_dir 的组与绑定。
修改 state_dir 会切换到另一份状态；PID 注册不会恢复。

热更新先准备规则 bank，再切换并更新域绑定。编译、容量检查失败保留旧规则；
切换后的持久化或绑定错误需查看回执和 status，不能笼统理解为“失败就完全未生效”。
不保证所有 domain 同时切换。公开 API 和旧 RPC 都不能热改基线或 daemon 开关。

## 三种接入方式

### 启动前接管

```bash
sudo censorguardd launch --config /etc/censorguard/base.yaml
# 另一个终端，daemon READY 后
sudo censorguardctl policy apply --policy worker-policy --file worker.yaml
sudo censorguardctl bind --domain worker --policy worker-policy
sudo censorguardctl spawn --domain worker -- agent COMMAND_ARGS
```

持续测试可启动一个交互式 shell，在里面多次执行文件、命令和网络操作：

```bash
sudo censorguardctl spawn --domain worker -- bash
# 在新 bash 中执行待测操作；exit 结束
```

sudo 启动的目标默认继承 root 身份；测试普通用户时明确使用 `runuser -u USER -- bash`。
管理 daemon、ctl 和观察日志的终端应在受控树之外。

### 接管已运行的 agent

```bash
sudo censorguardctl attach --pid AGENT_PID --domain worker
sudo censorguardctl status
sudo censorguardctl unattach --pid AGENT_PID
```

选择 agent 自身的根 PID。跨 UID 操作需要 root；同 UID 操作仍受 socket ACL 和
协议权限约束。先发布组和绑定，再 attach。

### 自注册与 DSH

agent 自己连接 `launch.sock`，v2 `register_self` 传 `scope` 和 `group`。
daemon 用 SO_PEERCRED 确定真实 PID，自动回填子孙。已有公开绑定时采用域的全部组；
指定非空 group 必须是成员，空 group 表示采用已有绑定，不能清除约束。

DSH `AttachSelfClient` 直接连接 `dsh.sock`，提交白名单内的 `policy_group`、
可选 `instance_hint`，默认回填子孙。自动生成独立 domain，管理员可继续 bind 其它组。
`status_self` / `tree_self` 只查询调用者自身。心跳检测 boot ID 变化并重新接入。

```text
censorguard-grpc [--config PATH]
```

gRPC 支持 Status、GetPolicy、ValidatePolicy、ApplyPolicy、GetConfig、SubscribeEvents。
组写限 `daemon.dsh_self_groups`，基线与开关只读；SetSwitches 等旧管理 RPC 返回
PermissionDenied。gRPC 不代表 agent PID 自吸附。详情见 [DSH 插件指南](DSH插件指南.md)。

## 已移除的公共接口

ctl 不再提供 `reload`、`tree`、`policy-dump`、`untrack`、`set`。
不提供 `attach/spawn --policy`、`attach --seed`、daemon `--track-pid` / `--domain`
或省略 launch 的启动方式；路径参数统一写入 daemon 配置。未知或重复参数报错。

静态检查与构建入口为 `make check`、`make test`、`make build`、`make bpf`。
实机接入验收入口为 `make integration-policy-entry`，需 root、BPF LSM 和插件依赖。
[验收记录](策略管理验收.md)区分此前完整测试与本轮针对性验收；
本轮完整编译、测试和 DSH Web 联调另行执行。
