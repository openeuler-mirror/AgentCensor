# CensorGuard 命令手册

本手册是 CLI 的唯一规范。路径和守护进程运行设置只写在配置文件的
`daemon` 段；命令行不再接受 socket、BPF、state 或 gRPC 路径参数，也不提供别名。

## 构建产物

安装的入口只有：

| 二进制 | 作用 |
| --- | --- |
| `censorguardd` | eBPF 强制守护进程 |
| `censorguardctl` | 控制、策略、审计和受控启动统一入口 |
| `censorguard-grpc` | DSH WebUI 使用的非特权 gRPC 适配器 |

`censorguard-audit` 和 `censorguard-exec` 的功能已经分别并入 `censorguardctl audit`
和 `censorguardctl spawn`，不再安装或作为独立 CLI 使用。

## 配置文件

默认配置为 `/etc/censorguard/base.yaml`。所有程序只接受一个全局选项：

```text
--config PATH
```

策略仍使用根级 `rules`、`groups` 和 `domains`。路径和运行设置写在 `daemon`：

```yaml
daemon:
  bpf_object: /usr/lib/censorguard/enforce.bpf.o
  control_socket: /run/censorguard/ctl.sock
  event_socket: /run/censorguard/events.sock
  launch_socket: /run/censorguard/launch.sock
  dsh_socket: /run/censorguard/dsh.sock
  ui_socket: /run/censorguard/ui.sock
  state_dir: /var/lib/censorguard
  socket_group: censorguard
  gateway_user: null
  dsh_self_groups: [censorguard-dsh-default]
  dns_refresh_seconds: 60
  spawn_grpc: true
  grpc_bin: /usr/bin/censorguard-grpc
  grpc_listen: 127.0.0.1:50051
```

未知的策略字段和 `daemon` 字段会被拒绝。`daemon` 字段全部有默认值，缺少该段时仍可使用默认安装路径。
显式指定的配置文件必须存在，`dns_refresh_seconds` 必须大于零。

## censorguardd

```text
censorguardd launch [--config PATH] [--check-config]
                    [--track-pid PID --domain NAME] [--duration SECONDS]
```

`launch` 启动空策略守护进程，之后由 ctl 下发策略。省略 `launch` 时从配置文件加载
策略。`--check-config` 只校验配置和策略，不加载内核；`--duration` 用于测试，
`--track-pid` 用于启动时纳管进程。其余路径、socket、权限、DNS 和 gRPC 设置均来自
`daemon`，对应旧的 `--ctl-sock`、`--event-sock`、`--state-dir`、`--spawn-grpc` 等
参数已经删除。

## censorguardctl

```text
censorguardctl [--config PATH] COMMAND ...
```

控制 socket 从配置的 `daemon.control_socket` 读取。

### 状态和策略

```text
censorguardctl status
censorguardctl tree
censorguardctl policy-dump
censorguardctl reload [--file FILE | --stdin] [--policy GROUP] [--dry-run]
censorguardctl set [--enable-file on|off] [--enable-exec on|off] [--enable-net on|off]
                   [--audit-file on|off] [--audit-exec on|off] [--audit-net on|off]
censorguardctl policy apply --policy GROUP (--file FILE | --stdin) [--dry-run]
```

`status`、`tree` 和 `policy-dump` 不接受额外参数。`reload` 不带输入时重新加载配置
中的策略；`set` 至少需要一个开关。`policy apply` 只更新命名策略组。

### 进程和域

```text
censorguardctl attach --pid PID [--domain NAME] [--seed] [--policy GROUP]
censorguardctl untrack --pid PID
censorguardctl bind --domain NAME --policy GROUP
censorguardctl spawn [--domain NAME] [--policy GROUP] [--keep] -- COMMAND [ARGS...]
```

`spawn` 在目标命令执行前自动纳管进程；默认退出后解除跟踪，`--keep` 保留跟踪。
`--domain`、`--policy` 是唯一字段名，位置参数和 `--name`、`--group` 等别名均不支持。

### 审计流

```text
censorguardctl audit [--kind N] [--pid PID]
```

事件 socket 从 `daemon.event_socket` 读取，`--kind` 支持 FILE=1、EXEC=2、NET=3、
GUARD=4。此命令持续输出事件直到 daemon 关闭连接。

## censorguard-grpc

```text
censorguard-grpc [--config PATH]
```

UI socket、事件 socket 和监听地址全部从同一配置的 `daemon` 段读取。它不再接受
`--sock`、`--ev-sock` 或 `--listen`。

## 策略 YAML

```yaml
rules:
  - file deny+audit /etc/shadow
  - exec deny /usr/bin/nc
groups:
  restricted:
    rules:
      - net deny 0.0.0.0/0
domains:
  - name: worker
    group: restricted
```

每条规则为 `file|exec|net allow|deny[+audit] TARGET`，规则编译失败会拒绝整个
请求并保留旧策略。

## 构建

```bash
make check
make test
make build
```

`make build` 只生成 `censorguardd`、`censorguardctl` 和可选的 `censorguard-grpc`；
`make install` 不再安装已合并的 audit/exec 独立二进制。
