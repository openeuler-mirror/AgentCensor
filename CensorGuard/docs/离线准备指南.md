# openEuler 24.03 LTS SP3（aarch64）准备机离线准备指南

本文用于准备机构建 CensorGuard 核心组件的离线部署包。准备机通过 DNF 安装必要依赖，构建用户态程序
和 BPF 对象，生成目标主机安装文件树、离线 RPM 仓库和校验清单，最后打包分发。

目标主机上的检查、依赖安装、安装文件和启动流程见
[目标主机离线部署指南](离线部署指南.md)。

## 1. 角色、架构和部署包目录

本指南以准备机和目标主机均使用 openEuler 24.03 LTS SP3 aarch64 为例。准备机可联网，
通过 DNF 安装必要工具、获取依赖并完成构建；目标主机在离线环境中安装和运行。
用户态程序、BPF 对象、配置和 systemd 文件应来自同一源码快照。

准备机建立目录：

```bash
export CG_KIT="$HOME/CensorGuard"
mkdir -p "$CG_KIT"/{rpms/runtime,keys,release,records,docs,tools}
```

目录内容（这些目录用于暂存部署材料，不改变任何 RPM 的默认安装位置）：

```text
rpms/runtime/                 目标主机运行库及传递依赖
keys/                         RPM 签名公钥
release/rootfs/               目标主机安装文件树
release/CensorGuard-standalone-aarch64.tar.gz
tools/check-deployment-env.sh   目标主机部署前只读环境检查器
tools/cg-deploy.sh            目标主机一键部署编排脚本
records/                      RPM、工具链、构建和校验记录
docs/                         随包分发的使用文档
SHA256SUMS                    部署文件校验清单
```

目标主机按同样的 `$HOME/CensorGuard` 解包离线部署包，脚本位于 `<离线部署包>/tools/`，
部署产物按相对路径识别，无需重新传参。`tools/cg-deploy.sh` 是目标主机的一键部署入口，
解包后按部署指南第 2 节执行，它依次完成环境检查、补齐运行依赖、安装文件与初始配置、
启动并验证。安装到目标主机系统的文件见
[部署指南第 1 节](离线部署指南.md#1-离线部署包解包与校验)。

文档只有 `docs/` 一处，不复制到 `release/rootfs/` 或系统路径：
`tools/` 放在目标主机执行的脚本，`docs/` 放使用者阅读的文档，`records/` 是准备机记录。

## 2. 准备离线 RPM

准备机配置经部署方确认的 openEuler 24.03 LTS SP3 aarch64 软件源。示例源如下：

```text
https://repo.openeuler.org/openEuler-24.03-LTS-SP3/OS/aarch64/
https://repo.openeuler.org/openEuler-24.03-LTS-SP3/everything/aarch64/
```

安装准备机工具：

```bash
sudo dnf --setopt=install_weak_deps=False install dnf-plugins-core createrepo_c
cp /etc/pki/rpm-gpg/RPM-GPG-KEY-openEuler "$CG_KIT/keys/"
sudo rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-openEuler
```

下载目标主机运行库的完整依赖闭包：

```bash
cg_repo() {
  dnf --disablerepo='*' \
    --repofrompath=cg-sp3-os,https://repo.openeuler.org/openEuler-24.03-LTS-SP3/OS/aarch64/ \
    --repofrompath=cg-sp3-all,https://repo.openeuler.org/openEuler-24.03-LTS-SP3/everything/aarch64/ \
    --enablerepo=cg-sp3-os --enablerepo=cg-sp3-all "$@"
}

cg_repo download --resolve --alldeps --setopt=install_weak_deps=False \
  --destdir="$CG_KIT/rpms/runtime" \
  libbpf elfutils-libelf zlib libgcc
```

为目标主机运行依赖目录生成离线仓库元数据：

```bash
createrepo_c "$CG_KIT/rpms/runtime"
```

记录包名、架构和签名：

```bash
find "$CG_KIT/rpms" -name '*.rpm' -exec \
  rpm -qp --qf '%{NAME} %{EPOCHNUM}:%{VERSION}-%{RELEASE} %{ARCH}\n' {} \; \
  | sort > "$CG_KIT/records/delivery-rpms.txt"
find "$CG_KIT/rpms" -name '*.rpm' -exec rpm -K {} \; \
  > "$CG_KIT/records/rpm-signatures.txt"
```

目标主机使用 openEuler 自带的 DNF、RPM、systemd、tar、gzip、awk 和基础 Shell 工具；运行时离线仓库只包含
CensorGuard 的直接运行依赖及其传递依赖。准备机使用经部署方确认的 openEuler 24.03 LTS SP3 仓库快照。

## 3. 通过 DNF 安装准备机必要依赖

本节安装 daemon、ctl、BPF 对象构建和离线打包所需的依赖。准备机在线使用批准的
openEuler 24.03 LTS SP3 aarch64 软件源，DNF 同时安装各包的传递依赖。

| RPM 包 | 工具或文件 | 构建用途 |
| --- | --- | --- |
| `rust`、`cargo` | `rustc`、`cargo` 及配套 Rust 标准库 | Rust 编译、依赖获取和链接 |
| `gcc` | `cc`、`gcc` | Rust 默认本机链接器入口及 C 探针编译 |
| `glibc-devel` | C 标准头文件、链接文件和启动对象 | 本机 C 编译和用户态程序链接 |
| `clang` | `clang` 和配套编译器资源头文件 | BPF 编译及 Rust 内核适配层的 C 文件编译 |
| `llvm` | `llvm-strip` | 处理生成的 BPF 对象 |
| `bpftool` | `bpftool` | 从准备机内核 BTF 生成 `vmlinux.h` |
| `binutils` | `ar`、`ld` | C 静态归档和本机链接 |
| `make` | `make` | 执行 BPF 构建目标 |
| `pkgconf` | `pkg-config` | 查询开发库的头文件、链接参数和版本 |
| `libbpf-devel` | libbpf 头文件和链接文件 | 编译 BPF 头文件依赖及用户态 libbpf 适配层 |
| `elfutils-libelf-devel` | libelf 头文件和链接文件 | 用户态 libelf 链接 |
| `zlib-devel` | zlib 头文件和链接文件 | 用户态 zlib 链接 |
| `bash`、`coreutils`、`findutils`、`sed` | Shell、`install`、`sha256sum`、`sort`、`find`、`xargs` 等 | 构建脚本、文件安装、清单及校验生成 |
| `tar`、`gzip` | 归档和压缩工具 | 离线部署包生成 |
| `ca-certificates` | 系统 CA 证书 | Cargo 通过 HTTPS 获取依赖 |
| `dnf-plugins-core`、`createrepo_c`、`rpm` | `dnf download`、`createrepo_c`、`rpm` | 第二节的离线依赖准备和签名查询 |

执行安装。所有 RPM 均使用 DNF 安装到发行版默认位置：

```bash
sudo dnf --setopt=install_weak_deps=False install \
  rust cargo \
  gcc glibc-devel clang llvm bpftool binutils make \
  pkgconf libbpf-devel elfutils-libelf-devel zlib-devel \
  bash coreutils findutils sed tar gzip \
  ca-certificates \
  dnf-plugins-core createrepo_c rpm
```

在准备机发布源码根目录设置构建环境。源码目录放在部署包目录之外，工具直接使用 DNF 安装到系统默认位置的命令：

```bash
export CG_SOURCE="$PWD"
```

项目 `Cargo.toml` 声明最低 Rust 版本为 1.88，应确认准备机仓库提供的工具链满足该要求。
源码的 `rust-toolchain.toml` 记录了项目工具链版本；本流程不安装或调用 rustup，直接使用
DNF 提供的工具链。

准备机确认架构和 BTF：

```bash
test "$(uname -m)" = aarch64
test -r /sys/kernel/btf/vmlinux && printf 'BTF 可读\n'
```

架构应为 `aarch64`。本流程从可读的 `/sys/kernel/btf/vmlinux` 构建；准备机只需提供
BTF，目标主机的 BPF LSM 能力在部署前检查和首次启动时确认。

在线获取锁定的 Rust 依赖，并记录工具链和依赖信息：

```bash
cd "$CG_SOURCE"
cargo fetch --locked
rustc -Vv > "$CG_KIT/records/rustc.txt"
cargo --version > "$CG_KIT/records/cargo.txt"
cp Cargo.lock rust-toolchain.toml "$CG_KIT/records/"
rpm -q rust cargo gcc glibc-devel clang llvm bpftool binutils make \
  pkgconf libbpf-devel elfutils-libelf-devel zlib-devel \
  > "$CG_KIT/records/build-packages.txt"
```

## 4. 编译 BPF 对象和用户态程序

使用准备机当前运行内核的 BTF 构建 BPF 对象。准备机和目标主机均为
openEuler 24.03 LTS SP3 aarch64，BTF 由准备机在构建阶段提供：

```bash
cd "$CG_SOURCE"
make bpf BPF_ARCH=arm64 \
  VMLINUX_BTF=/sys/kernel/btf/vmlinux
cargo build --locked --offline --release \
  -p censorguard-daemon -p censorguardctl
```

这里的 BTF 用于准备机生成 CO-RE 所需信息。部署前需检查目标主机当前内核的 BTF 和能力，
BPF 首次加载时再由内核验证 CO-RE 和程序；同发行版、同架构仍需核对实际能力。
构建完成不能代替目标主机的运行验收。目标主机内核能力缺失时按报告处理，内核或启动配置
调整涉及重启的，由系统管理员安排维护窗口。

构建产物为：

```text
target/release/censorguardd
target/release/censorguardctl
bpf/enforce.bpf.o
```

## 5. 生成目标主机安装文件树

```bash
cd "$CG_SOURCE"
CG_ROOTFS="$CG_KIT/release/rootfs"
install -d "$CG_ROOTFS/usr/sbin" "$CG_ROOTFS/usr/bin" \
  "$CG_ROOTFS/usr/lib/censorguard" "$CG_ROOTFS/etc/censorguard" \
  "$CG_ROOTFS/etc/censorguard/stages" \
  "$CG_ROOTFS/usr/lib/systemd/system" "$CG_ROOTFS/usr/lib/sysusers.d" \
  "$CG_ROOTFS/usr/lib/tmpfiles.d"
chmod 0750 "$CG_ROOTFS/etc/censorguard/stages"
install -m 0755 scripts/check-deployment-env.sh \
  scripts/cg-deploy.sh "$CG_KIT/tools/"
install -m 0755 target/release/censorguardd "$CG_ROOTFS/usr/sbin/"
install -m 0755 target/release/censorguardctl "$CG_ROOTFS/usr/bin/"
install -m 0644 bpf/enforce.bpf.o "$CG_ROOTFS/usr/lib/censorguard/"
install -m 0644 config/deployment.yaml \
  "$CG_ROOTFS/etc/censorguard/base.yaml.example"
install -m 0640 config/deployment-0*.yaml \
  "$CG_ROOTFS/etc/censorguard/stages/"
install -m 0644 packaging/systemd/censorguardd.service \
  "$CG_ROOTFS/usr/lib/systemd/system/"
install -m 0644 packaging/sysusers/censorguard.conf "$CG_ROOTFS/usr/lib/sysusers.d/"
install -m 0644 packaging/tmpfiles/censorguard.conf "$CG_ROOTFS/usr/lib/tmpfiles.d/"
install -m 0644 README.md LICENSE NOTICE \
  docs/离线准备指南.md docs/离线部署指南.md docs/部署环境检查.md \
  docs/策略编写与保护范围.md \
  "$CG_KIT/docs/"
tar -C "$CG_ROOTFS" -czf \
  "$CG_KIT/release/CensorGuard-standalone-aarch64.tar.gz" .
```

部署材料按用途分开放置：

| 位置 | 内容 | 目标主机侧用途 |
| --- | --- | --- |
| `release/rootfs/` | 装到目标主机系统的二进制、BPF 对象、配置和 systemd 文件 | 安装时解包 |
| `tools/` | `check-deployment-env.sh` 环境检查、`cg-deploy.sh` 一键部署 | 在目标主机执行 |
| `docs/` | 使用者阅读的文档 | 阅读 |
| `records/` | RPM、工具链、构建和校验记录 | 追溯用 |

`tools/` 中两个脚本都以 `0755` 安装，目标主机用 `sudo bash <路径>` 执行。`cg-deploy.sh`
调用同目录的 `check-deployment-env.sh`，读取其 `--findings` 结构化结论分派安装与人工
处理项，因此准备机打包时使用配套版本的检查器脚本。脚本运行前提与检查器一致：Bash 4.2+、
`coreutils`、`tar`、`gzip`、`awk`、`rpm`、`dnf`、`systemctl`，全部由目标主机发行版
自带，离线部署包中随附的 `rpms/runtime` 提供运行库。

配置使用 `.example` 文件名，目标主机首次安装时复制为 `base.yaml`，已有配置按原文件保留。
`stages/` 中的四份阶段文件是可直接使用的完整基线配置，每份独立通过 `--check-config`，
后续只通过替换活动的 `/etc/censorguard/base.yaml` 来切换阶段。

`docs/` 随包分发的文件和用途：

```text
离线准备指南.md             构建、依赖准备和打包流程
离线部署指南.md             目标主机部署主流程
部署环境检查.md             检查器参数、报告字段和采集边界
策略编写与保护范围.md       目录保护、exec 参数匹配与通配符边界
README.md LICENSE NOTICE    版本、许可和来源标识
```

本指南随离线部署包分发，便于使用者追溯依赖准备、构建和打包过程。

`censorguardd.service` 中的 `Documentation=file:/usr/share/doc/censorguard/README.md`
指向系统文档路径。离线部署不再安装该目录，`systemctl status` 会显示该项无法解析，
以离线部署包 `docs/` 下的文档为准。需要使用该字段时，把 `Documentation=` 改为
可访问的文档地址，或删除该行后重新打包。

## 6. 生成校验清单并分发

```bash
cd "$CG_KIT"
find ./rpms/runtime ./keys ./release ./records ./docs ./tools \
  -type f -print0 | sort -z | xargs -0 sha256sum > SHA256SUMS
cd "$(dirname "$CG_KIT")"
tar -czf CensorGuard-aarch64.tar.gz \
  CensorGuard/rpms/runtime CensorGuard/keys CensorGuard/release \
  CensorGuard/records CensorGuard/docs CensorGuard/tools CensorGuard/SHA256SUMS
sha256sum CensorGuard-aarch64.tar.gz > CensorGuard-aarch64.tar.gz.sha256
```

`tools/` 目录下的两个脚本一并列入清单。新增或修改脚本后按本节重新生成，
目标主机解包后的 `sha256sum -c SHA256SUMS` 覆盖到部署脚本本身。

通过受控介质分发以下文件：

```text
CensorGuard-aarch64.tar.gz
CensorGuard-aarch64.tar.gz.sha256
```

离线部署包包含目标主机运行依赖、安装文件、环境检查脚本、一键部署脚本、构建记录和文档。
外层校验值随经部署方确认的可信渠道一并分发。

目标主机侧步骤见 [目标主机离线部署指南](离线部署指南.md)：在 `$HOME/CensorGuard` 解包并校验，
然后执行 `sudo bash "$CG_OFFLINE/tools/cg-deploy.sh" all` 完成环境检查、依赖安装、文件安装
与启动；需要逐步执行或排障时按该指南第 3 节操作。
